# 07 AI NPC 叙事系统设计

> 本文把 01–06 的叙事设计落成**可实现的系统**，重点回答：AI NPC 能自由对话，怎么还能保证剧情成立、谎言一致、线索可解？

---

## 1. 总体架构

```
             ┌─────────────── 剧情导演 Director ────────────────┐
             │ 硬节拍日历 · storylet 池 · 张力曲线 · 拉回机制     │
             └──────┬───────────────────────────────┬───────────┘
                    │ 选中的 storylet / 场景目标     │ 世界状态变更
                    ▼                               ▼
┌────────────┐  ┌─────────────────────────┐  ┌──────────────────┐
│ 真相层     │  │  NPC 对话运行时          │  │ 世界状态          │
│ Canon (C*) │─►│  角色卡 + 知识切片        │◄─│ 变量 / flags      │
│ 只读       │  │  + 记忆检索 + 场景目标    │  │ 关系轴 / 时间     │
└────────────┘  │  → LLM → 结构化输出      │  └──────────────────┘
┌────────────┐  │    (台词 + 工具调用)      │  ┌──────────────────┐
│ 信念层      │─►│                         │─►│ 线索板 / 版本档案 │
│ 说辞层      │  └─────────────────────────┘  │ 证据库            │
└────────────┘             │                  └──────────────────┘
                           ▼
                   ┌────────────────┐
                   │ 校验器 Validator│  事实冲突 / 禁区 / 安全
                   └────────────────┘
```

**原则**：剧本决定"发生什么"，AI 决定"怎么说"，校验器保证"没说错"。

## 2. 三层知识模型

| 层 | 内容 | 谁写 | LLM 可否修改 |
|---|---|---|---|
| **真相层 Canon** | 03 第6节的 C01–C23 | 编剧 | ❌ 只读 |
| **信念层 Belief** | 每个 NPC 相信什么、相信几分（例：晴晴相信秦岳资产，置信度随幕次变化） | 编剧设初值，系统按事件更新 | ❌ 只能通过事件更新 |
| **说辞层 Version** | 每个 NPC 对每类听众、每个话题"会怎么说" | 编剧写骨架，LLM 生成表层 | ✅ 表层措辞可变，**主张不可变** |

### 2.1 知识切片（每次对话的输入）
LLM 不读全部 Canon。每次对话只注入：
1. 该 NPC **知情**的事实；
2. 该 NPC 对**当前听众**的说辞骨架；
3. 当前场景目标（来自导演）；
4. 检索到的相关记忆（见第5节）；
5. 禁区清单。

> 设计意图：不给 LLM 它"不该知道"的信息，从根上杜绝"芳姐突然说出南屿绑架案"这类穿帮。

## 3. 场景目标（Scene Goal）

每段 AI 对话都由导演下发一个结构化目标，例如 MQ-19"语音聊"：

```yaml
scene: MQ-19_voice_call
npc: xu_qing
listener: player
must_convey:            # 本场必须传达的主张
  - V3.claim.qin_used_my_phone
  - V3.claim.we_were_in_london
  - V3.claim.rico_picked_her_up
may_reveal:             # 玩家问到时才可透露
  - V3.claim.qin_said_she_lives_better_than_you
must_not_reveal: [C11, C10, C13]
tactics_allowed: [deflect, victim_flip, loyalty_test]
exit_conditions:
  - all must_convey delivered AND turns >= 6
  - player_hangs_up
  - turns >= 25          # 防止无限聊
on_exit: { set: [flag.v3_heard], unlock: [MQ-20] }
```

- `must_convey` 保证主线信息一定送达（即使玩家只是一直聊天，NPC 也会把话题带过去）。
- `tactics_allowed` 限制 NPC 在本场可用的招式（见 04 的招式与破绽）。

## 4. 谎言账本（Lie Ledger）—— 晴晴的核心系统

晴晴要能**对不同的人撒不同的谎，同时对同一个人保持一致**，让矛盾只在**跨听众**或**跨时间**时暴露（这本身就是线索）。

```yaml
topic: chen_mo_identity
versions:
  - audience: player        claim: "男朋友 / 未来老公"         since: ACT1
  - audience: fang_jie      claim: "朋友，帮忙开车的"            since: ACT1
  - audience: qin_yue       claim: "不存在；有个司机"           since: ACT1
  - audience: outsiders     claim: "我养着他，每天给零花钱"      since: ACT3
  - audience: feng_yi       claim: "疯子、渣男，骗了我几百万"     since: ACT5
consistency: per_audience   # 对同一听众必须一致
leak_rules:
  - when: player overhears call with qin_yue → 版本档案记录差异
  - when: player talks to outsider (cred>=40) → 获得 outsiders 版本
```

**运行规则**：
1. LLM 每生成一句涉及账本话题的台词，必须调用 `assert_claim(topic, version_id)`；
2. 校验器检查该版本是否允许对当前听众使用；
3. 不允许就重新生成，或回退到编剧写好的保底台词；
4. 所有 `assert_claim` 自动写入玩家的**版本档案**（只记录玩家在场或得知的部分）。

**版本演化**：晴晴的说辞会随压力升级（第三幕"赵慧是谁"的解释链）。账本中用 `supersedes` 字段表示"新版本替代旧版本"。被替代的旧版本**不会消失**，玩家可以拿旧版本当面质问，触发她的 DARVO 招式。

## 5. 记忆系统

采用 Generative Agents 结构（记忆流、反思、计划），针对剧情做了约束：

| 记忆类型 | 例子 | 保留策略 |
|---|---|---|
| **剧情记忆**（编剧预置） | "我曾在赌场让他睡沙发" | 永久 |
| **事件记忆**（系统写入） | "12月5日他说没碰过我的手机，停顿了2秒" | 永久，打重要性分 |
| **对话记忆**（LLM 摘要） | "他问过我三次赌场工作具体做什么" | 按重要性衰减 |
| **反思**（定期生成） | "他最近不再像以前那样相信我了" | 每幕结束时生成，编剧审核模板 |

- 检索公式：`score = 新近度 × 重要性 × 相关性`（沿用斯坦福小镇的做法）。
- **持久化是硬需求**：调研中《燕云十六声》被诟病的问题是"重新登录后记忆消失"。所有记忆都存进存档，跨会话可用。
- **记忆可以被利用**：晴晴会翻旧账（检索高怨恨值的记忆）；芳姐会记得你是否替她说过话。

## 6. 证据与三角印证系统

### 6.1 证据对象
```yaml
evidence:
  id: EV-electric-bill
  type: document          # document / chat / screenshot / recording / testimony / transfer / photo / record
  source: in_world        # in_world（亲眼所见）/ testimony（他人所说）/ public（公开记录）
  supports: [claim.player_lived_there]
  contradicts: [xu_qing.V(fang_jie).lives_alone]
  reliability: 0.9
  acquired_by: MQ-14
```

### 6.2 线索板
- 软木板 UI（参考《Shadows of Doubt》）。玩家把**主张**（谁说了什么）和**证据**钉上去，并拉线建立关系：支持 / 矛盾 / 同一人 / 时间先后。
- 系统**不自动**下结论。系统只标记：
  - 🔴 **矛盾**：两条主张冲突，或主张与证据冲突；
  - 🟢 **印证**：同一结论被不同来源的证据支持。

### 6.3 三角印证判定
关键结论需要满足：**至少一条 in_world 证据 + 至少一条他人证词 + 至少一条实物或公开记录**，且来源互相独立。

| 关键结论 | in_world | testimony | public / 实物 |
|---|---|---|---|
| 晴晴就是失踪案中的闺蜜 | 你拍的照片比对 | 小雯协查、Maya | 报道中的名字、"和K分手"截图 |
| 赵慧的钱是捞人骗局 | 亲眼见她双手机转接通话 | 赵慧、周志强 | 收款名单、转账时间线 |
| 珠宝报案是构陷 | 12月4日的经过 | 芳姐、Coco | 转账记录、通话记录、租约 |
| VAWA 计划 | 拉扯循环记录 | Coco | 移民律所 logo |

满足后，结论卡变为"已印证"，计入 `evidence[case]`。
**三线索原则保底**：每个结论的线索分布在 ≥3 个不同的任务里，漏掉任意一个仍然可解。

### 6.4 被推翻的认知
第一幕的两个认知锚点（"她是受害者""他只是经济犯"）以**特殊卡片**形式钉在板上，会给某些检定带来负面修正。第四幕卷宗揭示后，卡片被盖上"已推翻"印章，修正消失，并解锁回顾。

## 7. 对话玩法动词

| 动词 | 机制 | 适用 |
|---|---|---|
| **倾听** | 不打断，NPC 会说得更多（也更容易出现矛盾） | 所有 |
| **追问** | 针对上一句主张深挖，消耗 NPC 耐心 | 所有 |
| **出示** | 从证据库拿出证据，NPC 必须回应（承认 / 解释 / DARVO） | 审讯、对质 |
| **诈** | 假装知道某事（玩家自由输入）；NPC 按"心虚度"判断是否上当 | 晴晴、梅姨、冯逸 |
| **共情** | 降低防备，可能换来真话，也可能被利用 | 芳姐、赵慧、晴晴 |
| **沉默** | 不说话；部分 NPC 会自己补话（晴晴会，芳姐会更紧张） | 所有 |
| **调解** | 在两方之间提方案（序章、委托板） | 纠纷 |
| **设界** | 明确拒绝（"这种事情我不会干"） | 晴晴 |

### 7.1 被诈：NPC 诈玩家（MQ-22）
- 晴晴的诈问：先问 A，再突然问 B，观察反应。
- 系统评估玩家的自由输入：
  - **事实冲突**：回答与 flags 矛盾（`opened_suitcase = true` 却说"没打开"）；
  - **过度解释**：回答长度和细节明显多于问题需要；
  - **反问**："怎么了？"会被记录为一个信号（原作中晴晴正是从这里判断的）；
  - **语音停顿**：仅语音模式下启用；
  - **恢复原状得分**：来自 MQ-21。
- 综合得出晴晴的判断，影响第五幕。**不提示玩家"正确答案"**，因为原作主角自己也没弄明白她是怎么发现的。

### 7.2 被操控：自我怀疑系统
- 晴晴的 DARVO 每生效一次，`doubt` 上升；`doubt` 高时：
  - 内心声音"欲望"和"和事佬"更频繁地插话；
  - 部分对质选项被替换成道歉选项（例："就算这件事是我的错……"）；
  - 线索板上的证据显示为"你确定吗？"（UI 轻微失焦）。
- **对抗手段**：回看证据（"锚定"）、打电话给阿康复盘、听"妈妈的声音"。这对应原作的认识："这种相处方式已经影响到了我自己的判断。"
- 设计红线：系统不能让玩家觉得被游戏本身欺骗，只能是被**角色**操控。所有被操控时做出的选择，事后都能在线索板上看到"当时的证据其实是什么"。

## 8. 内心声音（《极乐迪斯科》式）

| 声音 | 触发属性 | 风格 | 作用 |
|---|---|---|---|
| 🟣 妈妈 | `clarity` / 警觉 | 温和、简短、朴素 | 提醒异常 |
| 🔴 欲望 | `attachment` | 自我说服、轻佻 | 为她找理由 |
| 🟢 和事佬 | `cred` / 性格 | 劝和、怕麻烦 | 调解加成，但会让你吃亏 |
| 🔵 老侦探 | 调查经验 | 冷静、列清单 | 发现物件细节和时间矛盾 |

- 由小模型生成，每次 ≤ 2 句，使用编剧提供的语料风格。
- 每种声音有**固定锚点台词**（来自原作，如"人家才25岁，经历再复杂能有多复杂？"），在关键节拍必定出现。

## 9. 流言网络（涌现层）

- 华埠的 NPC 之间按社交图传播信息，每传一跳有**失真率**（数字夸大、人物替换、动机附会）。
- 例：晴晴对外说"我养着他" → 阿珍那里变成"陈默欠她钱" → 老邝那里变成"听说老陈在外面骗女人"。
- 玩家的 `cred` 会受流言影响；玩家也可以**主动辟谣**（出示证据给关键节点 NPC，例如老邝，他是流言枢纽）。
- 流言条目也是"主张"，可以钉在线索板上，用来**溯源**，即找到流言的源头。

## 10. 剧情导演

### 10.1 硬节拍日历
```yaml
- date: 2025-04-26  beat: MQ-09   preconditions: []           # 无论如何都会发生
- date: 2025-07-10  beat: MQ-15   preconditions: []
- date: 2025-12-04  beat: MQ-21   preconditions: []
- date: 2026-01-10  beat: MQ-24   modifiers: [MQ-22.verdict]
```
- 游戏时间可以由玩家推进（睡觉、等待），但硬节拍不能跳过；导演会在节拍前 3–7 天安排**预兆 storylet**。

### 10.2 张力曲线
- 每个 storylet 有张力值（-2 到 +3）。导演让近期张力的移动平均贴合目标曲线：第一幕缓升，第二幕拉扯，第三幕陡升，第四幕峰值，第五幕高位震荡，终幕释放。
- 防止连续三次高压（晴晴吵架 + 冻卡 + 威胁）造成疲劳。高压之后插入日常委托或朋友闲聊。

### 10.3 拉回机制
玩家长时间不推进主线时，导演依次启用：
1. 晴晴的消息、电话、撒娇、"缺个东西"（她本身就是最强的拉回机制）；
2. 朋友来电（冻卡阶段的老钟）；
3. 流言传到玩家耳中；
4. 最后才强制推进日期。

## 11. 安全与内容护栏

| 风险 | 护栏 |
|---|---|
| 现实人物、真实案件 | 全部虚构化（见 02 对照表）；Canon 中不含真实姓名；校验器屏蔽原作真实姓名和真实网名 |
| 犯罪方法泄露（绑架、洗钱、移民欺诈） | 禁区规则：任何 NPC 不描述操作细节；VAWA 只解释到"有独立申请路径"这个层级 |
| 性内容 | 亲密场景一律黑屏和暗示处理；LLM 不生成露骨内容 |
| 暴力 | 南屿事件只以文件和证词出现；导演事件中的威胁不演变为实际暴力 |
| 法律建议 | 律师类 NPC 只给方向，并带"建议咨询专业律师"的设定化台词 |
| 玩家诱导 NPC 出戏 | 参考 Ubisoft NEO NPC 的做法：区分"刁难角色"（角色内回应）与"辱骂、越界"（角色内冷处理，必要时结束对话） |
| 受害者尊严 | 鹿鸣的下落在任何结局都不确定；版本四中对受害者的污名化说法，必须在版本档案中与反证并列展示 |

## 12. 模型与成本分层（建议）

| 角色层级 | 例子 | 模型 | 说明 |
|---|---|---|---|
| T0 核心 | 晴晴 | 最强模型 | 谎言账本、长期记忆、复杂招式 |
| T1 重要 | 芳姐、赵慧、冯逸、阿珍、老邝、Harlow、警官 | 中高档模型 | 场景目标驱动 |
| T2 功能 | 委托板 NPC、乘客、邻居 | 小模型 + 模板 | 参数化生成 |
| T3 声音 | 内心声音、旁白变体 | 小模型 | 短句、风格化 |

- 所有 T0 和 T1 的关键节拍保留**编剧保底台词**：模型出错或超时，就回退到写死的台词，保证剧情不断。
- 结构化输出：台词与工具调用（`assert_claim`、`reveal_secret`、`update_relation`、`end_scene`）分离，便于校验和日志回放。

## 13. 开发验证清单（叙事 QA）

- [ ] 每个关键结论 ≥3 条独立线索，且分布在 ≥3 个任务中
- [ ] 每个硬节拍在任意玩家状态下都能触发
- [ ] 晴晴对同一听众的说辞在 100 轮自动对话测试中无矛盾
- [ ] 任意 NPC 不泄露非知情事实（自动红队：诱导式提问 500 例）
- [ ] 禁区（C11 承认、C13 下落、犯罪细节）在对抗测试中零突破
- [ ] 所有结局可达；E6 条件在设计范围内可达，但罕见
- [ ] 记忆跨存档、跨会话保持一致
